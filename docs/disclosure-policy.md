# Public disclosure policy

The purpose of this showcase is to demonstrate engineering skills without exposing operational systems or private intellectual property.

## Intended public content

- High-level research goals and engineering practices
- Synthetic diagrams and illustrations
- Publicly approved, non-sensitive technical summaries
- Small, independent examples created expressly for publication (future work)

## Excluded material

- Original private source code or Git history
- Passwords, API keys, tokens, certificates or identity material
- Real IP addresses, ports, internal DNS names, host identifiers and storage paths
- Deployment topology, authentication/authorization implementation details and active security findings
- Private logs, traces, prompts, model output containing sensitive information and personal or customer data
- Unsupported claims that a component or the complete system is production-ready

## Review requirements

Before each publication, check the full Git history, assets and metadata (not only the latest README), verify third-party rights and licences, and obtain explicit project-owner authorization. No private repository should be made public merely because selected files appear safe.
